## What's inside
1. `CLAUDE.template--general-repo.md`: a CLAUDE.md skeleton for any repository. Commands, conventions, boundaries, verification.
2. `CLAUDE.template--python-microservice.md`: the same idea, tuned for a Python API or microservice. Thin handlers, one place for config, strict test rules.
3. `CLAUDE.template--multi-agent-project.md`: the rules file for repos where several agents work in parallel. Roles, file ownership, the packet rule, verification, cost discipline.
4. `ORCHESTRATION_CHECKLIST.md`: the one page checklist I run before, during, and after any multi agent session.

## How to use it
1. Pick the template closest to your project and copy it into your repo root as `CLAUDE.md`.
2. Replace every `[BRACKET]` with your real commands and conventions. Delete the sections that don't apply to you. Seriously, delete them.
3. Keep it short. This file loads into every agent session you'll ever run on the project, so every line has to earn its place.
4. Print the checklist, or pin it somewhere. Run it until it becomes habit.

## Why this stuff works
Most agent failures aren't model failures. They're management failures. The brief was vague. Two agents edited the same file. Nobody checked the output. A premium model burned an afternoon doing bulk work a cheap one handles fine. These templates exist to close those four holes: self contained packets, one writer per file, verify don't trust, and models picked by role instead of by hype.
